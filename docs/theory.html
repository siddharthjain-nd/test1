From pixels to people

How a photograph becomes 512 numbers, why four ways of grouping those numbers behave so differently, and what three rounds of measurement turned out to mean — including where the first round was wrong.

A single self-contained file — no network needed, nothing to install. Kept in docs/theory.html beside the code it describes; the decisions it cites are logged in PLAN.md §6 and the runs in DEVLOG.md.

01What the machine actually sees

Four stages in a line. Each takes the output of the last and throws away everything else — by the time grouping happens, the photograph is long gone and only numbers remain.

02Turning a face into numbers

What it means

An embedding is 512 numbers describing a face — a coordinate, a single point in a space with 512 axes. The model was trained so that one person's photographs land close together and different people land far apart. Nothing in the numbers means "nose width"; they are just a position, learned so that distance means identity.

The maths
v̂ = v / ‖v‖   where   ‖v‖ = √(v₁² + … + v₅₁₂²) Every face is scaled onto a sphere of radius 1, so only direction carries information — a brighter photograph no longer moves the point further out.
cos(θ) = â · b̂ = â₁b̂₁ + … + â₅₁₂b̂₅₁₂ The cosine similarity. 1.0 means identical direction, 0 means unrelated. Every threshold in this project is one of these numbers.
‖a − b‖² = 2 − 2·cos(θ) On unit vectors, straight-line distance and cosine carry the same information. That let the code use Euclidean library routines unchanged — and avoid a 64,000 × 64,000 matrix that would have needed 32 GB.

Why the numbers cluster by person at all

L = −log   es·cos(θy + m) ⁄ ( es·cos(θy + m) + Σj≠y es·cos θj ) ArcFace. An angular margin m is added to the correct answer's angle before scoring, making the model's own job harder. Demanding the right answer anyway forces each identity into a tight cone with empty space between cones. That empty space is what makes clustering possible.
Measured

Unrelated faces score 0.086 on average. Two photographs of one person typically exceed 0.5. That gap is the entire signal everything below works with.

04Four ways to make piles

All four receive the same input — 63,878 points on a sphere — and differ entirely in what question they ask of that geometry.

dmreach(a, b) = max( corek(a), corek(b), d(a, b) ) HDBSCAN. corek(a) is how far a sits from its k-th neighbour — how lonely it is. Lonely points are pushed away from everything, so a person with two photographs can never form a cluster at any setting.
group(a) = { b : a path a → … → b exists, every edge with cos ≥ t } Connected components. Membership is transitive — A links B, B links C, all three land together. One pass over a graph, entirely governed by t.
label(v) ← argmaxℓ   Σu ∈ N(v), label(u) = ℓ w(u, v) Chinese Whispers. Each face adopts whichever label carries the most weight among its neighbours. One weak edge cannot drag a group across — it has to outvote everything else.

Agglomerative repeatedly merges the two nearest groups. More principled, and it must track distances between every pair of live groups.

Measured

Agglomerative needed 6.1 GB at 63,878 faces and killed an 8 GB machine. Memory sat near 40% through the graph phase, then spiked in one burst too fast for swap to absorb.

05Chaining: fatal at 0.30, essential at 0.60

Transitivity is the same mechanism whether it helps or destroys. Only the threshold decides which.

06How the scoring works

Precision: when it puts two faces together, is it right? Recall: did it find all of someone's photographs? Merging two people hurts precision; splitting one person hurts recall.

PB³ = (1/N) Σi |C(i) ∩ L(i)| / |C(i)|  ·  RB³ = (1/N) Σi |C(i) ∩ L(i)| / |L(i)|  ·  F1 = 2PR/(P+R) Counted per face. C(i) is the pile face i landed in, L(i) everyone who truly shares its identity. The harmonic mean stays low unless both are high.
ARI = ( RI − E[RI] ) / ( max RI − E[RI] ) The Rand Index minus what random guessing would have scored. When F1 and ARI disagree sharply, trust ARI.

Two more corrections to the first version of this page

It called HDBSCAN structurally wrong for this problem. Tuned, it reaches 0.9521 — second place, not last. Its 0.478 was an untuned figure being compared against tuned rivals.

It also said recall 0.800 showed the ceiling was the method rather than the photographs. True, but the ceiling was further off than it looked: recall reached 0.931.

What survives

  • Algorithm choice is worth more than model choice — 0.478 → 0.961 against 0.887 → 0.961 — but both matter, and the first version wrongly dismissed the second.
  • The simplest method still won. Connected components is one pass over a graph, and it beats density clustering and label propagation — above its cliff, and it is the worst of all of them below.
  • Bigger is not better. ResNet100 is twice ResNet50's size and lost by 0.014.

08Picking the threshold without labels

The gold set holds 1,499 faces. The library holds 63,878. A threshold tuned on the first can be wrong on the second, because connected components needs only one bad edge to weld two people, and the chances of that edge grow with the number of pairs, not faces.

Welding needs no labels to detect: it shows up as a pile that suddenly doubles.

Measured, with no labels involved

The welding point is 0.49, and 0.51 is the loosest safe setting — which is also the best-scoring one on the gold set. Two independent methods, the same answer.

09The one measurement that counts

Every number so far came from identities used to choose the settings. Twenty-four people were reserved from the start and never consulted. They were scored once.

Before opening them, the tolerance was fixed by asking how much a 24-person score wobbles by luck alone: 2,000 random 24-person draws from the tuning half.

Which errors remain

Consistent across both halves, so real: bad-quality faces 0.515, tiny faces 0.89, marginal quality 0.91, profile 0.89, middle era 0.90. Every one is about the face being hard to read, not about the method.

Slices that reverse between the halves — photos-per-person, beauty-filtered — are noise on 221 faces and were read as findings once before they were checked.

10Where the human comes in

Precision 0.976, recall 0.906. The machine mixes people rarely and splits them sometimes, so the human's job is mostly joining, not separating.

The design rule that follows: a clustering is disposable, a human decision is not. So decisions are recorded against face identifiers, which come from detection and never change — never against pile numbers, which are renumbered by every re-run.

The question that decides whether this is a product

Naming eight thousand piles is not something anyone will do. Whether that is what this asks depends entirely on how lopsided the piles are — and pile sizes look very lopsided indeed, with 106 of them holding 26,358 faces. If a few hundred names cover most of a library, the design holds. If not, the clustering has to join more per pile, or poor faces have to be kept out of the queue altogether.

That number is not yet measured, which makes it the most important thing still unknown — more important than any threshold on this page.
